# Tarefas: Segurança da autenticação e da sessão

**Entrada**: Documentos de design em `/specs/20261101-232504-security-auth/`

**Pré-requisitos**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/), [quickstart.md](quickstart.md)

**Testes**: obrigatórios (Princípio VII, TDD). Em toda fase os testes vêm **antes** da implementação, cada um diz qual deve falhar (Red) e por quê, e o Red é **visto** antes do Green. "Red por não compilar" é aceito **só como primeiro passo**, quando o símbolo ainda não existe. Onde o Red de **comportamento** depende de tipos novos (fases B, C, D e E2), uma tarefa de **ESQUELETO MÍNIMO** cria antes os tipos e as assinaturas **sem comportamento**, para tudo compilar; só então se roda os testes e se registra que falham pelo motivo esperado, e só depois se implementa. Para cobertura de comportamento que a fase anterior já entregou, o Red é provado por **mutação temporária de produção** (tarefa explícita), nunca pulado. **Nenhuma tarefa comenta, apaga ou desliga teste.**

**Organização**: por **fase** (0, A, B, C, D, E1, E2, F), exatamente as do plano, cada uma terminando num **checkpoint** com build e testes verdes, para revisão e commit separados. Os rótulos de história da spec: **[US1]** rotas fechadas e Swagger · **[US2]** troca de senha/perfil derruba o token · **[US3]** JWT e chave · **[US4]** login em tempo uniforme · **[US5]** limite por origem e por conta · **[US6]** portas locais · **[US7]** testes de autorização de todo endpoint.

## Formato: `[ID] [P?] [Story] Descrição`

- **[P]**: pode rodar em paralelo (arquivos diferentes, sem dependência de tarefa incompleta).
- Caminhos relativos à raiz do repositório. `Api`, `Application`, `Domain`, `Infrastructure` e `Tests` abreviam `src/Backend/AccessControlSystem.{Api,Application,Domain,Infrastructure,Tests}`.
- `TE-nn` aponta uma linha de **"Testes existentes afetados"** e `FX-nn` uma linha de **"Ajustes de fixture"** (ambas no fim deste arquivo). **Nenhuma tarefa está marcada como concluída.**

## Regras fixas (valem para todas as tarefas)

1. **Sem commits.** O agente não faz commit nem push. Cada checkpoint é um ponto de revisão e de commit **separado**, feito pelo revisor (sugestões no fim).
2. **Parada em cada checkpoint.** Em cada checkpoint (0, A, B, C, D, E1, E2, F): parar, preencher a tabela "Registro de números", reportar os números e a lista de arquivos alterados (`git status --short`), e aguardar o commit do revisor antes de seguir.
3. **Integridade das entregas** (constituição): não apague, pule nem enfraqueça teste. Só mudam os testes da tabela "Testes existentes afetados", e só como ali descrito. Se outro teste precisar mudar, ou qualquer verificação falhar, **pare e reporte a saída real**. Nenhum `Skip`, nenhum threshold afrouxado, nenhum aviso suprimido. **É proibido comentar, apagar, desligar ou condicionar um teste para "ver o Red"**: o Red de comportamento vem do esqueleto (regra 10), e a mutação temporária (T098) é feita no código de **produção**, nunca no teste.
4. **Edição**: use as ferramentas de edição (preservam CRLF e acentos em UTF-8). **Nunca** `sed -i` em arquivo versionado: o `sed` do Git Bash descarta o `CR` dos arquivos CRLF.
5. **Migrations**: a migration é gerada **somente** por `dotnet ef migrations add AddSecurityVersionToOperators` e aplicada **somente** pelo Migrator (`docker compose run --rm migrator migrate`). **Nenhuma tarefa roda `dotnet ef database update`**, nem bundle, nem script de `dotnet ef migrations script`: a `SeedAdmin` criaria o administrador de senha fixa numa base nova.
6. **Sem pacote NuGet ou npm novo ou atualizado** (Princípio II). O relógio falso dos testes é uma classe do projeto de testes; o relógio real é o `TimeProvider` da BCL.
7. **Sem estático**: nada novo com campo `static` em Application ou Infrastructure (`NoStaticTenantStateTests`). O hash fictício e o registro de falhas são campos de **instância** de singletons.
8. **Constituição e `.env` do dono não são tocados.** As emendas de redação (R-21) são pendência do dono do projeto. Na validação ao vivo, valores temporários vão por **variáveis exportadas no shell** (têm precedência sobre o `.env`), nunca editando o `.env`.
9. **Gates canônicos**:
   - **GATE-BACK**: `cd src/Backend && dotnet build Backend.slnx && dotnet test Backend.slnx` (Docker ligado). Esperado: `0 Aviso(s)`, `0 Erro(s)`, `Com falha: 0`, `Ignorado: 0`.
   - **GATE-FRONT**: `cd src/Frontend && npm run typecheck && npm test && npm run build`. Esperado: tudo verde, 0 falhas.
   - **Só rápidos**: `dotnet test Backend.slnx --filter "Category!=Integration"`.
   - **GATE-VULN** (constituição, gates antes do PR; roda na tarefa final T120): `cd src/Backend && dotnet list Backend.slnx package --vulnerable --include-transitive` e `cd src/Frontend && npm audit --audit-level=high`. A saída é registrada e reportada. Os achados **já conhecidos** não bloqueiam e pertencem à spec 04b: no backend, `SSH.NET` (transitivo do Testcontainers, suprimido por `NU1903` com justificativa em `AccessControlSystem.Tests.csproj`); no front, `vite` e `source-map-js`. Qualquer achado **novo** bloqueia e deve ser reportado. Nada é suprimido, atualizado ou corrigido aqui.
10. **Esqueleto mínimo (tarefas `Txxxa`)**: contém só tipos e assinaturas, sem o comportamento novo; o que já existe hoje continua igual (por exemplo, `PasswordVerifier.Verify` só delega ao operador quando ele existe, como o código atual; `TryAcquireAttemptAsync` sempre devolve `null`). Cada arquivo ou trecho de esqueleto leva o comentário `// ESQUELETO (security-auth): substituir na tarefa Txxx`, que é **removido** na tarefa de implementação; a varredura T119 exige zero ocorrências de `ESQUELETO`. O esqueleto nunca altera nem enfraquece teste.
11. **Variáveis temporárias na validação ao vivo** (T110, T113, T116, T117): o `docker compose` lê o ambiente do **mesmo shell** em que roda, e variável de processo tem precedência sobre o `.env`. Cada tarefa dá o equivalente em **Git Bash** (`export X=...`, `unset X`) e em **PowerShell** (`$env:X = "..."`, `Remove-Item Env:X -ErrorAction SilentlyContinue`). Exportar e subir o compose têm de ser no mesmo shell; fechar o shell também limpa as variáveis.
